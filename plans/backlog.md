## Security (open)

Threat model context above — the deferred items are a deliberate decision, not an oversight.

- **Deferred for v1.0:** `update_saviour` / `deploy_update` package signature/checksum verification (currently only `zipfile.is_zipfile()`); ZMQ `ROUTER_HANDOVER` identity-hijack (a spoofed `module_id` silently steals another module's command stream); `/update/package` staying unauthenticated (modules fetch it with no admin password available). ZMQ CURVE auth/encryption, web UI TLS, Samba SMB3 sealing, fleet SSH-key/password rotation on clone — all framed as "closed-LAN only" caveats, v1.0 ships with that stated.
- **Web UI: single shared password, plaintext, no lockout** — Flask-SocketIO over plain HTTP, so the admin password is sniffable on every login/reconnect. `authStorage.js` caches it in `localStorage` indefinitely. `handle_login` has no rate-limiting/lockout and never logs failed attempts. `cors_allowed_origins="*"` widens this. Plan (login lockout + logging, session tokens with expiry, CORS lockdown, an access log, then named accounts): **`plans/remote-access-auth-hardening.md`** — the path that's actually exposed once the fleet is reached over Tailscale.
- **Per-module MJPEG livestream is unauthenticated** — `MJPEGStreamServer` (`src/modules/mjpeg_stream.py`) binds `0.0.0.0` on `:8080`–`:8083`, no auth; the browser hits module Pis directly (`streamUrls.js`). Any routed node (Tailscale included) can `curl` a live feed — which carries animal-procedure footage and identifiable faces. Plan (bind-narrowing + a token gate + optional controller proxy + a `stream.enabled_when_idle` toggle): **`plans/mjpeg-stream-auth.md`**.
- **No transport encryption on the Samba/CIFS export** — mount commands never set the SMB3 `seal` option; recorded data and briefly-`ps`-visible mount credentials cross the LAN in plaintext.
- **Controller services now bind the eth0 address only (branch `fix/bind-services-to-lan`, roadmap B2, 2026-09-30).** Flask/SocketIO + `/api/v1` (:5000) and the unauthenticated ZMQ bus (:5555/:5556) listen on the address `interface.listen_on` resolves to: `"lan"` (default) = the validated eth0 IP, `"all"` = the old every-interface behaviour, or a literal IP (`controller.py::resolve_listen_host`). The :80 redirect is `-i eth0`; Samba was already `lo eth0`. So none of them answer on wlan0 **or on the controller's Tailscale address** (unless the controller advertises `10.0.0.0/16` as a subnet route). The web UI is no longer on `localhost:5000`; reach it over Tailscale with `tailscale serve --bg http://10.0.0.1:5000` (HTTPS for free). The `wlan0`/WAN default-deny firewall (`SAVIOUR-WLAN-IN`, `configure_firewall()`) stays as the catch-all for non-SAVIOUR listeners (sshd); `src/controller/firewall_status.py` verifies it at startup (ERROR + alert) and in controller health (System page "Firewall not active on …"). Trust model: the tailnet is only the owner's machines, so `tailscale0` stays unfiltered. **Still open:** the module role has no firewall and module MJPEG (`:8080+`) binds `0.0.0.0` (modules normally have no wlan0); no source-subnet restriction on `eth0`. See `docs/NETWORK_FIREWALL.md`, `plans/firewall-interface-scoping.md`.
- **Fleet image cloning never rotates the OS user's password / `~/.ssh/authorized_keys`** — `multiclone.sh`/`clone_prep.sh` regenerate SSH *host* keys + machine-id but never the login credential; whatever the master image's imager set is shared, unrotated, across every cloned device.
- **`push_credentials.sh` disables SSH host-key checking** (`StrictHostKeyChecking=no`) and passes the password as a literal SSH command-line arg (briefly `ps`-visible on the module).
- **`saviour.service` runs fully as root with no systemd hardening** — no `NoNewPrivileges`, `ProtectSystem`, capability bounding. Reasonable for `ptp4l`/`phc2sys` (raw clock hardware); not obviously necessary for the whole ZMQ/web/update surface.

## Architectural concerns

Larger structural issues requiring significant refactoring — recorded so they aren't lost.

- **Module base class is a god object** — `module.py` (~1275 lines) owns config, export, PTP, recording, health, network, commands, lifecycle. No concern testable in isolation. Needs a composition refactor across all module types.
- **`web.py` is a 2000-line grab-bag** — sessions, config sync, chunked update uploads, deployments, bug-report collection, NAS probing (3 duplicated mount/umount snippets), time setting, power control, all in two giant registration methods. Split into Flask blueprints.
- **Controller/module/frontend "variant" selection is hardcoded and conflates three axes of change** — a single `DEVICE_TYPE` string drives `get_python_path()`'s `variants/${DEVICE_TYPE}/${DEVICE_TYPE}_controller.py` convention *and* `build_frontend()`'s `VITE_VARIANT`, forcing a 1:1 pairing between "new frontend variant" and "new controller Python class" even when the variant needs zero backend logic (`loom_controller.py` is a pure no-op subclass). **Shipped so far:** `examples/` → `variants/` rename (2026-08-13); menu auto-detection from `*/variant.conf` `NAME`/`DESCRIPTION` (2026-08-17); `variant.conf` carries `FRONTEND` + module `APT_PACKAGES`. **Proposed full fix:** extend `variant.conf` with `ENTRYPOINT`/`CONFIG_FILE`; make the unit file *invariant* (one fixed `ExecStart=... src/main.py` launcher that reads `DEVICE_TYPE`/`DEVICE_ROLE` and dynamically imports the entrypoint). **Blocking prerequisites (open):** (1) fixed launcher + dynamic dispatch; (2) `__file__`-relative config loads (`load_controller_config()` uses CWD-relative `os.path.abspath()`, only works because `WorkingDirectory` is per-variant today); (3) invariant `configure_service()` — `update_saviour()` never regenerates the unit file, so a path-moving code push leaves a deployed device's unit file stale and the service down. Smaller cleanup worth doing first: extract genuinely-shared `basic/{components,pages}` into `src/controller/frontend/src/shared/`.
- **Samba is the wrong export transport** — designed for Windows interop; adds credential management, mount failure modes, an unreliable driver stack on a homogenous Linux PoE network. `rsync` over SSH or an HTTP PUT endpoint would be simpler. High effort — rewrites all export logic.
